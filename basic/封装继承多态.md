一、封装
1. 是什么
把数据（属性）和操作数据的行为（方法）打包进一个类里，并控制外部能看到多少——该藏的藏起来，该露的露出来。
class People:
    def __init__(self, name):
        self.name = name
        self.__secret = '私密信息'   # 双下划线 → 私有属性

    def get_secret(self):
        return self.__secret         # 通过方法间接访问

3. 私有属性的读取
p = People('张三')
print(p.name)            # ✓ 张三
print(p.__secret)        # ✗ AttributeError
print(p._People__secret) # ✓ 能读到（改了名），但强烈不建议这么干
print(p.get_secret())    # ✓ 正确姿势：通过方法
更 Pythonic 的做法是 @property，把方法伪装成属性：
@property
def secret(self):
    return self.__secret

print(p.secret)          # 像访问属性一样调用方法
4. 易错点
- 单下划线不是真私有：_name 只是提醒别人别乱动，Python 不做任何限制。
- 双下划线会被改名：__secret 实际存成 _People__secret，所以直接在子类里用 __secret 也会出问题。
- 别用 dog.__animal_note 去读：私有属性要用类内部的方法（如 get_note()）间接取。
二、继承
1. 基本语法
class People:              # 父类：不继承别人 → 不写括号
    def __init__(self, name):
        self.name = name
    def hi(self):
        print('你好')

class Worker(People):      # 子类：括号里写父类
    def hi(self):          # 重写：方法名必须和父类一模一样
        print('我是工人')
2. 重写 __init__ 必须补调父类
子类一旦写了自己的 __init__，父类的就被整个盖掉，不会自动执行。
class Worker(People):
    def __init__(self, name, addr):
        super().__init__(name)   # ← 关键：喊父类回来初始化
        self.addr = addr
不写的后果：w.name 根本不存在，hasattr(w, 'name') 为 False。
3. super() 的真正作用
不是“调用父类”，而是“沿 MRO 队列找到下一个类，把方法交给它”。
单继承时“下一个”恰好是父类，所以看着像调爹；多继承时“下一个”可能是兄弟类。
写法
作用
super().__init__(name)
调下一个类的构造方法，让父类初始化属性（最常用）
super().greet()
调下一个类的普通方法，复用 + 扩展父类行为
两者机制完全相同，区别只在点号后面的方法名。__init__ 因为最常用，看着像 super 的专属功能，其实不是。
参数注意：super().__init__(name) 里不写 self（super 自动传），只给父类需要的参数。
4. 多继承与 MRO
class Flyer:
    def fly(self): print('飞行')
class Swimmer:
    def swim(self): print('游泳')
class Duck(Flyer, Swimmer):    # 多个父类，逗号隔开
    pass
MRO（方法解析顺序） = 方法查找的队列，可用 Duck.__mro__ 查看。
C3 算法三条规则（决定队列顺序）
以菱形继承为例：
class Goods: ...
class Things(Goods): ...
class Shape(Goods): ...
class Pen(Things, Shape): ...
MRO 为：Pen → Things → Shape → Goods → object
1. 子类优先于父类：Goods 是共同父类，被排到最后。
2. 先继承的优先：括号里 Things 在前，所以 Things 压过 Shape。
3. 广度优先于深度：同层的 Shape 抢在父类 Goods 前面（深度优先会让 Goods 跑到 Shape 前面，违反规则①）。
命中即停
方法查找从队首往右扫，找到第一个就立刻结束，不会把所有同名方法都调一遍。
- Pen().say() → 走到 Things 命中 → 调 Things.say()，Shape / Goods 根本不会被看。
- 括号反过来写 class Pen(Shape, Things) → MRO 变成 Pen → Shape → Things → Goods → object → 调 Shape.say()。
想让多个方法都执行：在每个类的方法里写 super().say() 接力传棒（协作式多继承）。末端的基类用空方法 pass 兜底，否则传到 object 没有该方法会报 AttributeError。
5. 易错点
- 重写 __init__ 忘调 super().__init__() → 父类属性丢失。
- super() 链里只要有一个类忘调 super()，链就断，后面的类全不执行。
- 多继承别滥用，适合“能力组合”；更复杂时优先用组合（self.flyer = Flyer()）而非继承。
三、多态
1. 是什么
同一个调用，不同对象给出不同行为。 调用方不关心对象具体是什么类，只管喊方法名。
2. 标准格式（三段式）
# ① 父类：定义通用方法
class 父类:
    def 方法名(self):
        ...

# ② 子类：继承父类，重写同名方法
class 子类(父类):
    def 方法名(self):        # 名字必须一模一样
        ...

# ③ 调用方：只喊方法名，不做类型判断
def 函数(obj):
    obj.方法名()

函数(子类())                # 传谁就执行谁的版本
3. 两种多态
继承多态（靠血缘）
class People:
    def hi(self): print('普通人')
class Worker(People):
    def hi(self): print('工人')
class Student(People):
    def hi(self): print('学生')

def say_hello(someone):
    someone.hi()             # 不判断类型

for p in [People(), Worker(), Student()]:
    say_hello(p)
输出：普通人 / 工人 / 学生。传 Worker 时喊 hi()，执行的是子类重写版——这就是“父类引用调用子类重写方法”。
鸭子类型（靠行为）
“如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。”
def make_it_quack(obj):
    obj.quack()

class Duck:
    def quack(self): print('鸭子：嘎嘎')

class Person:
    def quack(self): print('人模仿：嘎嘎')

class Rubber:
    def quack(self): print('橡皮鸭：吱吱')
三个类毫无继承关系（父类都是 object），只要有 quack() 就能被同一个函数统一调用。

4. 异常检测辅助（配合鸭子类型）
把“能不能调用”变成 True/False 反馈，避免程序崩溃：
def try_call(obj):
    try:
        obj.call()
        return True          # 成功
    except Exception as e:
        print(e)             # 别省！否则失败原因被吞掉
        return False
或提前探测：
if hasattr(obj, 'quack'):
    obj.quack()

关于三引号的重要说明
三引号 """ 的正当用途只有两个：文档字符串和多行文本。它不是注释语法。
- 用来“注释掉”大段代码是可以的，但开头和结尾必须分处两行，中间的内容才算字符串。
- 若字符串里本身含有 """，会提前闭合——这是第 6 条报错的根源。
- 临时封存少量代码，最稳的是每行前面加 #。
关于魔术方法的下划线
__init__、__name__、__mro__ 这类魔术方法 / 属性，前后各两条下划线，共四条。名字差一个字符（多一条、少一条、顺序反、掺零宽空格）就失效，而且编辑器通常不标红，只有运行时才暴露。
五、一句话速记
- 封装：把属性和方法装进类，私有的藏起来（双下划线），通过方法访问。
- 继承：子类白拿父类的方法；重写 __init__ 要手动 super().__init__() 补一声。
- super()：沿 MRO 队列找下一个，不是单纯“调爹”。
- MRO：子类优先、左边优先、广度优先；方法查找命中即停。
- 多态：调用方只喊方法名，传谁就执行谁的版本——有继承的靠血缘，没继承的靠鸭子类型。
- 鸭子类型：不问出身（什么类），只问本事（有没有这方法）。
- __init__：左 2 右 2 共 4 条下划线，少一条多一条都不行。
